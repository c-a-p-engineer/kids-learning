# ドキュメント案内

`docs/` は、現在の仕様、設計方針、ユーザーとの会話で決まった要件を整理して管理します。

## 読む順番

1. [コンテンツ一覧](コンテンツ一覧.md)
2. [子ども向けUI方針](design/子ども向けUI方針.md)
3. 変更対象のコンテンツ仕様書
4. [会話・意思決定記録](conversations/README.md)
5. 必要に応じて [アーキテクチャ](architecture.md)

## 設計資料

- [architecture.md](architecture.md): 現在の構成、データ保存、ルーティング、ビルド
- [design/子ども向けUI方針.md](design/子ども向けUI方針.md): 視認性、タッチ操作、スマホ・タブレット対応

## 会話・意思決定記録

- [conversations/README.md](conversations/README.md): 記録対象と書式
- `conversations/YYYY-MM-DD-<topic>.md`: 日付単位の要約記録

会話ログは全文ではなく、実装や運用に影響する判断を再現できる要約にします。

## 更新ルール

- 画面・導線・保存形式を変更したら、対応仕様書を同じPRで更新する
- 新しいコンテンツを追加したら、この索引と `コンテンツ一覧.md` を更新する
- 共通UI基準を変更したら `design/子ども向けUI方針.md` を更新する
- ユーザーとの会話で重要な判断が決まったら `conversations/` に記録する
- 実装されていない内容は「検討中」「保留」と明記する
