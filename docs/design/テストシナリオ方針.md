# 子ども向けテストシナリオ方針

子ども向けコンテンツのQAを、実装者が「普通に一回遊べた」だけで完了しないための共通方針。

この文書は個別コンテンツの学習内容を定義しない。各仕様書、`子ども向けUI方針.md`、`学習セッション方針.md`、`共通ナビゲーション.md` を前提に、**子どもの実際の操作で壊れやすい経路をシナリオ化する**。

## 基本原則

テストは次の4種類を分ける。

1. **Happy path** — 想定する主要操作で完了できる
2. **Mistake path** — 誤タップ、連打、間違い回答でも操作不能にならない
3. **Recovery path** — 戻る、再挑戦、画面回転、再読込後に継続・復帰できる
4. **Accessibility / device path** — 小画面、文字拡大、キーボード、reduced motion等でも主要操作が残る

成功ケースだけでなく、子どもが説明を読まずに触ることを通常状態として扱う。

## Scenario card

個別コンテンツの新規追加・大きなUI変更では、必要なものだけ次を記録する。

```text
scenario:
user state / prerequisite:
device / viewport:
action:
expected visible result:
expected saved state:
recovery if mistaken:
what must not happen:
```

形式を埋めること自体を目的にしない。既存自動テストや仕様書で十分なケースは重複記述しない。

## 共通シナリオ

### 1. First-action discovery

- コンテンツを直接URLから開く
- 長い説明を読まなくても最初に押す・触る対象が分かる
- 無操作でも危険な状態変更が起きない
- 最初の操作後、結果が視覚的に分かる

### 2. Correct completion

- 最短の正しい操作列で1セッションを完了する
- 完了状態が明確に見える
- 次の行動（再挑戦、戻る、次へ）が分かる
- 保存対象がある場合は仕様どおり保存される

### 3. Wrong answer / wrong tap

- 間違った対象を選ぶ
- 正解と失敗を色だけに依存せず理解できる
- 一回の誤操作でセッション全体が壊れない
- 失敗後に次の正しい操作へ戻れる

### 4. Rapid repeated input

- 同じボタンや対象を素早く複数回押す
- score、進捗、保存値が二重加算されない
- animation / timer / event listenerが重複開始しない
- 操作不能なoverlayが残らない

### 5. Navigate away and return

- セッション途中でトップへ戻る
- 再度コンテンツを開く
- 仕様上保存する状態とリセットする状態が区別される
- 古いtimer / animation / audioが裏で継続しない

### 6. Reload

- 途中または完了後にページを再読込する
- LocalStorageの既存形式を読める
- 壊れた・古い保存値がある場合も画面全体が起動不能にならない
- migrationがある場合は後方互換ケースを確認する

### 7. Orientation / resize

- スマホ縦から横、またはviewportを大きく変える
- 主要ボタンが画面外へ消えない
- canvas / coordinate系コンテンツで当たり判定と表示位置がずれない
- 横スクロールが主要操作に必要にならない

### 8. Text zoom

- ブラウザ文字サイズを約200%へ拡大する
- 主要操作と結果が残る
- button textが切れて意味不明にならない
- 固定heightにより重要UIが隠れない

### 9. Keyboard / focus

- Tabで主要操作へ移動できる
- focus-visibleが見える
- Enter / Space等、既存UIが対応する基本操作を壊さない
- focus trapを意図せず作らない

### 10. Reduced motion

- `prefers-reduced-motion` で主要な意味が失われない
- animationを減らしても正解・失敗・完了が文字や形で理解できる

## Content-specific risk selection

すべてのケースを全コンテンツで同じ重さで実行しない。

### Timer-based

追加確認:

- 0秒境界
- 一時停止 / 画面離脱
- 二重timer開始
- 完了後のtimer残存

### Drawing / pointer / canvas

追加確認:

- pointer down中の画面外移動
- touch cancel
- viewport resize後の座標
- 太い指でも対象を選べる

### Audio-based

追加確認:

- autoplay制限
- mute状態
- audio load失敗
- 音声なしでも主要進行が分かる

### Saved progress

追加確認:

- 既存データ読み込み
- 空データ
- 部分的に壊れたデータ
- 新旧versionのmigration

## Learning UX review

技術的に動くことと、学習体験として成立することを分ける。

確認する。

- 一回の画面に判断対象が多すぎないか
- 正解後の演出が長く、次の試行を妨げないか
- 間違いを罰する演出が強すぎないか
- 操作の難しさと学習内容の難しさを混同していないか
- 読字能力を測るコンテンツでないのに説明文読解を前提にしていないか
- 保護者向け設定が子どもの主要導線へ混入していないか

## Automation boundary

自動テストへ向くもの:

- route
- state transition
- LocalStorage compatibility
- timer cleanup
- duplicate event prevention
- deterministic scoring
- invalid data handling

実画面確認が必要なもの:

- タップしやすさ
- 視線誘導
- 文字の読みやすさ
- animationのうるささ
- 画面回転後の実配置
- 子どもが説明なしで最初の操作を発見できるか

自動テストが通ったことを、Child UX確認の代替にしない。

## 完了条件

UIまたはインタラクションを変更した場合、少なくとも次を確認する。

- 主要Happy path
- 変更箇所に最も近いMistakeまたはRecovery path
- 対象端末サイズ
- 保存仕様へ影響する場合は既存データ互換
- animationへ影響する場合はreduced motion
- 実施していない手動確認を完了済みと報告していない
