# 子ども向けUI方針

## 1. 目的

子どもがスマートフォンやタブレットで、説明を長く読まなくても学習を開始できるUIを維持します。同時に、保護者が課題や履歴を管理でき、誤操作で記録を失いにくい構造にします。

## 2. 対象端末

基準となる確認サイズ:

- 小型スマートフォン縦: 360 x 640前後
- 一般的なスマートフォン縦: 390 x 844前後
- タブレット縦: 768 x 1024前後
- タブレット横・PC: 1024px以上

最小幅は320pxを想定します。端末固有のノッチやホームインジケーターには `env(safe-area-inset-*)` で対応します。

## 3. 情報設計

### 子ども向け画面

- 最初に「何をするか」を示す
- 主要な選択肢はカードまたは大きなボタンで提示する
- 1画面の主要目的は原則1つにする
- 補助設定は折りたたむか、保護者向け画面へ分離する
- 戻る操作の文言と位置を画面間で大きく変えない

### 保護者向け画面

- 課題追加、履歴、保存容量、削除をまとめる
- 削除・初期化は子ども向け画面に置かない
- 破壊的操作には対象と影響範囲を明示し、確認を求める

## 4. 視認性

- 本文は原則16px以上
- 補助文は12px未満にしない
- 見出し、本文、補助情報の差を文字サイズと太さで明確にする
- 背景と文字のコントラストを確保する
- 色だけで正解・不正解・選択状態を伝えない
- 絵文字やアイコンには、近接する文字情報またはアクセシブルな名前を付ける
- 長い文章を避け、ひらがな中心の短い指示を使う

## 5. タッチ操作

- 主要タップ領域は原則44 x 44px以上
- 隣接するボタン間に十分な間隔を設ける
- ドラッグ対象は指で隠れすぎない大きさにする
- `touch-action` を必要な領域に限定する
- ダブルタップや長押しを必須操作にしない
- スワイプだけでなくボタンでも操作できるようにする

## 6. レスポンシブ

### スマートフォン

- 1カラムを基本とする
- 主要操作は横スクロールなしで到達できるようにする
- ゲーム領域と操作ボタンの優先順位を明確にする
- 入力欄がフォーカスされた際に、16px未満の文字サイズによる自動ズームを発生させない

### タブレット・PC

- コンテンツカードは2〜3列にする
- コンテンツ内部の学習領域は読みやすい最大幅を設ける
- 単純に要素を巨大化せず、余白と複数列で視線移動を短くする
- 横画面でもゲーム領域が画面外へ押し出されないようにする

## 7. アクセシビリティ

- ブラウザのピンチズームを禁止しない
- 意味のある見出し順を維持する
- フォーム要素にラベルを付ける
- キーボードのフォーカス表示を明確にする
- モーダルには `role="dialog"` と `aria-modal="true"` を付ける
- 動的な成功表示には必要に応じて `aria-live` を使用する
- `prefers-reduced-motion: reduce` では演出時間を最小化する
- 強制カラーモードでも境界と文字が認識できるようにする

## 8. 演出と音

- 演出は「正解」「完了」「次へ進んだ」ことを理解させる目的に限定する
- 点滅を繰り返さない
- 長いアニメーションで操作を待たせない
- 音が再生できなくても進行可能にする
- 音量設定や端末のミュートを尊重する
- 同じ操作に対する効果音はコンテンツ間で極端に変えない

## 9. 文言

推奨:

- 「あそぶ」
- 「もういちど」
- 「できた！」
- 「一覧にもどる」
- 「おうちのひと」

避ける:

- 技術用語
- 長い否定文
- 原因が分からない「エラー」だけの表示
- 子どもを責める表現

通信や端末機能に失敗した場合は、できなかった機能と続行方法を短く示します。

## 10. 保存と安全

- 保存先がブラウザ内であることを保護者向けに示す
- `localStorage` の容量超過時に学習画面全体を停止させない
- 保存失敗時は、未保存であることを明示する
- 初期化や大量削除は確認ダイアログを必須とする
- 保存形式の変更時は既存データの移行または互換読み込みを行う

## 11. UI変更時の確認

- [ ] 主要操作は3秒程度で見つけられる
- [ ] スマホ縦で横スクロールしない
- [ ] タブレットでカードが過度に横長にならない
- [ ] 200%拡大でも開始・戻る・完了操作が残る
- [ ] Tabキーで主要操作を順番に移動できる
- [ ] フォーカス位置が見える
- [ ] 色を見分けにくい場合でも状態を判断できる
- [ ] 動きを減らす設定で操作不能にならない
- [ ] 子ども向け画面から破壊的操作を直接実行できない

## 12. 現在の実装

`src/styles/accessibility.css` は、既存コンテンツ固有CSSを維持したまま、次を補強します。

- セーフエリアと動的ビューポート
- フォーカス表示
- スキップリンク
- タッチ領域
- ポータルのスマホ・タブレット・PCレイアウト
- 設定の折りたたみ
- 文字拡大対応
- 動きを減らす設定
- 強制カラーモード
