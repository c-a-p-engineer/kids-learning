# 会話・意思決定記録

このディレクトリには、ユーザーとの会話から確定した要件、設計判断、運用ルールを要約して残します。

## 目的

- 後日の作業で「なぜこの仕様になったか」を確認できるようにする
- AIや開発者が、過去に却下された案を繰り返し提案するのを防ぐ
- 会話と実装・仕様書の対応を追跡できるようにする
- 未確定事項を確定仕様と混同しないようにする

## 記録する会話

- 新しいコンテンツや機能の要求
- 対象年齢、学習目的、端末などの前提
- UI・UXの採用案と却下案
- 保存、公開、ライセンス、運用に関する決定
- 実装後の重要なフィードバック
- 将来の作業に影響する保留事項

## 記録しない会話

- 雑談
- 一時的な作業状況
- 会話全文
- 氏名、住所、学校名などの識別情報
- 健康情報など、実装に不要な個人情報
- トークン、認証情報、秘密情報
- 画像や動画の個人的な内容そのもの

対象年齢や学習上必要な配慮は、個人を特定しない一般化した形で記録します。

## ファイル名

```text
YYYY-MM-DD-短いトピック.md
```

例:

```text
2026-07-27-repository整理.md
2026-08-02-数字なぞり教材.md
```

同じ日に同じトピックが続く場合は、既存ファイルへ追記します。

## テンプレート

```markdown
# <トピック>

- 日付: YYYY-MM-DD
- 状態: 確定 / 一部確定 / 検討中

## 背景・目的

## 要求の要約

## 決定事項

## 採用しなかった案

## 実施した変更

## 保留事項

## 関連

- Issue:
- PR:
- Files:
```

## 記述ルール

- 発言をそのまま並べず、意味を変えない範囲で要約する
- 決定事項と提案を明確に分ける
- 推測でユーザー意図を補完しない
- 保留事項には、未確定である理由を記載する
- 実装された場合は関連ファイルまたはPRを追記する
- 仕様書と矛盾する場合は、同じ変更内で仕様書を更新する

## 状態

- `確定`: 実装・運用の基準として採用済み
- `一部確定`: 一部は決定したが、数値・詳細・実装方法が未確定
- `検討中`: 案として記録するが、実装基準にはしない
