# PROJECT DOPAGAKI — V2 ゲームデザイン仕様案

状態: 実装前の採用方針 / 版: draft 0.1 / 起点: 2026-10-26
親: 01-evidence-review.md。児童の無限滞在や依存の最適化ではなく、学習定着・自律性・達成感を最適化する。

## 体験の中心

キャッチフレーズ: **「まなぶ → たたかう → できた！ → おぼえてた！」**

子どもは「学習科目の一覧」を眺める代わりに、2〜3つの選べるクエストを受け、敵や障害を倒す行為そのものとして算数・ことば・記憶・判断を用いる。演出を飾っただけの練習問題ではなく、解答が世界に因果を生む。

例:
- 敵のシールドにドット数が7つ並んでいる → 7を答えてシールドを壊す。
- 汽車のレールに「4、6、8、?」が現れる → 10を選んでレールを接続する。
- 魔法の扉が「いぬは さわらないで。でんしゃを えらんで」と言う → 待機して正しい対象へタップ。
- 昨日の「8と5、どちらが大きい？」を別の絵柄で正解 → 記憶が残っていた印として星がつく。

## ゲームループ

| 段階 | 画面/イベント | 教育上の機能 | 演出 |
|---|---|---|---|
| 1. 選ぶ | 2〜3件の分かりやすいクエストカード | 自律性・取りかかり | キャラが迎える、目標を音声/文字で知らせる |
| 2. 予想する | 1問、短い指示、一目で理解できる操作 | 能動的想起 | 敵が構える、列車が停止 |
| 3. 答える | タップ/ドラッグ/なぞる/長押し | 数・文字・判断の実践 | 入力即時反応、二重採点なし |
| 4. 修正する | 不正解時は理由・ヒント・もう一度 | 形成的フィードバック | 敵は待ち、攻撃をやり直す。嘲笑・減点演出なし |
| 5. 成長を見る | 明確な解決と達成 | 有能感・自己評価 | 正答や粘り強さに応じて短い演出、称号の条件が明確 |
| 6. 終わる | 3〜5課題など終了条件でリザルト | 区切り・自己調整 | ワールド復旧演出、次回の予告、終了を妨げない |
| 7. 覚えていた | 翌日・数日後のヒントなし再想起 | 保持の確認 | スキル結晶の成長、遅延報酬は習得の可視化 |

### 1セッションの原案

1. ウォームアップ1問（前にできた内容）
2. 要復習1〜2問（間隔復習）
3. 少し新しい課題1〜2問（支援付き）
4. ミニボス1問（既習知識の組み合わせ）
5. 結果・終了（任意で他の日に続き）

推奨は 3〜8分程度を**初期UIプリセット**とし、正確な最適時間を研究の確定数値だと主張しない。保護者が長さ、音量、演出強度、時間切れ方式を調整できる。原則として完了後の自動周回を行わない。

## 3つのワールド + 休息

### 1. かずの王国（数量・算数）

- ドットバースト → モンスターの数シールド
- かずの ならび → レール修復
- どっちが大きい？ → 2つの門のうち大きい数を選ぶ
- とけいを よもう → 時刻に合わせた列車の発車
- 将来の拡張候補: 20以内の足し算・引き算、具体物の数分解、日常の買い物ごっこ

### 2. ことばときおくの森（聞く・想起・言語）

- きいて！ミッション → 精霊からの1〜3段階指示、合図待ち、押さない指示
- えもじフラッシュ → 見た絵を思い出して秘密の扉を開く
- かきとりマスター → 符号/文字を書くことで魔法を完成
- えんぴつれんしゅう → 道をなぞってキャラクターを誘導

### 3. みる・かんがえる島（空間・判断）

- ぴったりシェイプ → パーツを正しい形へはめて基地を修理
- しんごうを わたれ！ → 交通状況を見て正しく停止・再開、遊び上の判断だけを評価
- 同じ目標でタップ/ドラッグ/長押しを選択できる代替操作を検討

### 4. からだで遊ぶ広場（STEP外）

- 30びょう バルーンアタックは身体を動かす短い体験として独立維持
- 運動を学習報酬の通貨にせず、座位・音無しでも成立する条件を別途検証
- カメラ映像は不保存・不送信、端末固定、適切な休息を維持

## 報酬システム：実力が主役

### 採用

- **XP（経験値）**: 出題を完了し振り返ったことに付ける。タップ連打・滞在時間では増えない。
- **マスタリースター**: その場で正解しただけでは最終到達としない。別の日に独力で想起できて初めて強く光る。
- **ワールド復旧**: 敵を倒すだけでなく、橋・列車・森・街などが元気になる。達成条件は予告する。
- **やり直しボーナス**: 不正解からヒントを使い学び直せたことを肯定。ただし独力の成績とは別集計。
- **子どもの選択**: 見た目の装飾や旅の順番を選べる。ランダム抽選による希少報酬ではない。
- **演出プリセット**: げんき / ふつう / しずか。内容・XP・習得判定はどのモードでも同一。
- **負けない仕組み**: 苛立ちの多いときは休憩/続きから再開可能。連続失敗で脅しやポイント没収を行わない。

### 不採用

- ランダム希少アイテム、ガチャ、確率的なご褒美（依存性目的）
- 「今日ログインしないと失う」、ストリーク切れの罰、強制通知
- エンドレスオートプレイ、無制限連続ステージ、終了ボタンの隠蔽
- 子ども同士のランキング、羞恥・嫉妬を使う競争
- 有料コンテンツ、広告、外部SNS・チャット、第三者追跡
- 誤答を強く責める演出、学力・IQ・発達診断の自動ラベリング

## 応答ロジック（初期ルール、効果未検証）

対象の習得判定は、最近の正誤だけでなくヒント利用・問題バリエーション・後日の正解を扱う。

- 初期: ヒント付きの易しい問題を出す。
- ヒントなしで連続正解、かつ異なる出題形式にも正解: 次の難易度候補を1問追加。
- 誤答または繰り返しヒント利用: 難易度を下げるか、具体物を提示。既に習得した別スキルは下げない。
- 後日復習: 未達なら1日後、達したら3日後、その後7/14日を**検証用初期値**として採用。
- 正解の速度は単独のランク基準にしない。じっくり考えて正解したことを低評価しない。
- 同じ問題IDをそのまま出し続けると選択肢配置を覚えてしまうため、表現・位置・数の組合せを変更する。
- 回答には「出題」「選択」「採点」「記録」の決定論的状態遷移を持たせ、多重タップで2回XPが増えない。

## 年齢・操作上のアクセシビリティ

- はじめて/読み書き前: 音声+絵+大きなタップ、短い1ステップ、読めない子に文字理解を強制しない。
- ひらがな学習中/幼児: 絵と文字併記、数を並べる具体物、模倣から独力へ段階化。
- 小学生: 数式・規則・選択理由を徐々に追加、得意なスキルは飛び級可能。
- 発達特性による操作差: 待機や指先操作の困難さを一律に認知能力の低さとしてスコア化しない。
- 音声無し、視覚優先、読み上げ、reduced-motion、静かな画面、指がずれたときの回復導線を並列維持。
- 画面の点滅や光刺激は安全基準に配慮し、必要な理解情報は文字/形/音の複数経路で表現。
- 子ども画面にデータ全削除や設定の破壊操作を出さない。

## 受け入れ条件（実装後に確認）

- 子どもが最初の一手を説明文なしで理解できる。
- 3〜5問で自動終了し、結果画面で終了と再挑戦が明確に分かれる。
- 間違えても誤答の理由に接続する具体的なフィードバックを得られる。
- 3種類以上の旧ゲームから同じセッション管理・記録APIへ正答/ヒントの情報を渡せる。
- 同一回答を2回送信しても履歴・XP・ボスHPが二重に変化しない。
- 翌日以降の問題がヒントなしで答えられたかを確認できる。
- 活発な演出を無効化してもスキル獲得と結果が同じ。
- 結果画面で自動的に次の問題を開始しない。
- ゲームの楽しさとは別に、7日後の保持を保護者が確認できる。

## 課題パック仕様の最小形

各問題には以下の概念が必要。正規型・DB設計は03-architecture-migration.mdに定義する。

- itemId / revision / skillId / activityType
- 表示・読み上げ内容、正解判定器、ヒント段階、難易度
- 課題のバリエーション生成条件（seed）
- 適応条件（正誤、ヒント、経過日数）
- どの技能を測るか。見た目のゲーム達成と学習技能を混同しない。

## 体験比較の事前仮説

- V1はゲーム別スコアを中心に蓄積するが、V2は技能別に後日想起できるかを追う。
- V2は導入時の楽しさと同時に、終了のしやすさを維持する。
- 旧V1より7日後保持率が上がるとはまだ言えない。比較用の同難度item setを準備し、必要な家庭内サンプルが揃って初めて判断する。
